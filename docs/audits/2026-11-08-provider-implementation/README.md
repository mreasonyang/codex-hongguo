# Provider 插件与双片源实施验收

日期：2026-11-08（Asia/Shanghai）。分支：`feat/video-source-adapters`。版本：0.0.34，尚未进入版本发布流程。

接口与安装方式见 [Provider 插件](../../providers.md)。本轮在原适配层方案上，按用户确认增加“内置 + 显式本地目录”的 Provider 发现、加载与生命周期。

## 已实施

- 统一适配契约、分页、限定 ID 与播放候选描述；Catalog 通过注册表调用来源。
- 红果迁入独立适配器，保留旧 ID、历史及缓存文件。数据库升级保留用户设置、旧推荐和观看进度。
- 新增黄果 hghub 站点适配器：匿名存储、线路切换、搜索分页、详情分集缓存、封面解密和 HLS 输入。
- 注册表支持内置与本地 `provider.json` / `.mjs` 插件；校验接口版本、ID、目录与入口、重复注册及必需方法，调用可选 dispose 并发出关闭 signal。
- 自定义 Provider 使用可跨平台保存的限定 ID，界面根据可用插件生成选源菜单。
- 媒体层支持 MPEG-TS AES-128 HLS，覆盖显式/默认 IV 和 key 轮换；清单、分片和 key 的目的地址均经过策略校验。
- 切源保存进度、停止旧播放、作废晚到结果与旧授权；各面板独立，历史及固定回合候选保持来源。
- 新 SDK 与许可、Provider 文档已进入 npm 包和离线 ZIP。

最终真实 MCP 结果见 [live-mcp.json](live-mcp.json)，绑定编译后服务 SHA-256。所有真实取流使用临时匿名档案和临时 SQLite；结束后清理媒体与状态。回执不保存剧名、媒体地址、密钥、能力值或原始站点响应。

浏览器测试与整集回执来自不同隔离运行：浏览器中的红果样本约 123 秒，从 1 秒续播并观察到约 20 秒；黄果从 1 秒续播并观察到约 11 秒。截图为已暂停的红果播放器，不包含上游媒体 URL。

## 红果回归重点

现有旧 ID、观看历史、默认静音与音量、任务开始/结束开关、固定推荐与可见后轮换、跨聊天隔离、CENC 解密、HLS/DASH、HEVC 转码回退、下一集预取、MCP 授权及块大小、安装/更新/卸载的原有测试均通过。

新增测试验证：切源后迟到的分集结果不能重新授予播放权限；迟到的片库和历史不能覆盖新来源；全局默认来源变化不切换已打开面板；坏插件不能覆盖内置红果；旧数据库升级后进度与明确关闭的设置保留。

MCP 界面资源升级到 v20，避免宿主继续使用没有选源控件的旧缓存；v19 及更早 URI 保留兼容读取，并由测试覆盖。

离线 SDK 测试显式禁止外网并提供空 profile store。实现期间修复了注入 fetch 在构造时过早捕获的问题；测试传输现在不会回退到真实站点。

## 证据边界

- Codex 主窗口 MCP App 的实际视频画面、声音和自然 Stop/Interrupt 尚未观察；本轮 `desktopPlaybackObserved` 保持 false。内置浏览器实播不替代该项。
- 测试主机为 macOS ARM64；Windows 专属运行项跳过，Windows/Linux 实机播放未验证。
- 真实线路故障、限流与签名过期未人为在生产站点触发；对应回退与有界刷新通过隔离测试。
- 首版仍为整集获取后播放。加密 init map、加密 byte range、discontinuity、SAMPLE-AES、DRM 与直播明确拒绝。
- 本地 Provider 是可信进程内代码。加载异常的隔离不构成对恶意插件的资源或进程沙箱。

## 复现

```sh
npm test
npm run package
npm run verify:install
node scripts/verify-providers.mjs --live
```

仅 `--live` 获取两片源各一集。`--browser-control <临时文件>` 可在成功后通过本地私有文件把一次性配对能力交给浏览器驱动；浏览器完成后删除该临时文件，验证器便继续记录回执并清理。不得打印或复制该文件内容到审计材料。
